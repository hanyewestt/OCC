# Phase 1 schema mapping

Status: source inventory captured on 15 October 2026 by replaying all four latest migration directories on a disposable PostgreSQL 18.6/PostGIS 3.6 instance. It did not connect to the local Compose database. Exact source columns and nullability are listed below; the target schema/constraints and import rules must be finalized and exercised by the phase-1 migration work before any real cutover. Never infer missing historical evidence.

## Ownership map

| Current schema/table | Target owner and table | Treatment |
| --- | --- | --- |
| `ingestion.*` operational tables/views | `ingestion.*` | Keep schema/history and owner. Preserve source classification, raw payload/checksum, timestamps, scopes and sequence semantics. |
| `bunching.source_processing_state` | `disruption.source_processing_state` | Copy current checkpoint state including retry deadline, rejection reason, demo scope, detection result, source sequence and optimistic version. |
| `bunching.consumer_state` | `disruption.consumer_state` | Copy singleton mode, selected demo ID, last consumed sequence, update time and version. |
| `bunching.alert_processing_state` | `disruption.disruption_processing_state` | Rename ownership/concept; retain stable scope identity, last source time, active episode, evidence observation IDs and pending confirmation snapshot. |
| `bunching.alert_event` | `disruption.disruption_event` | Generalize the event identity and event-kind while retaining bunching action, classification, demo scope, observed and expected headways, confirmation times, evidence IDs, rule version, timestamps and evidence snapshot. Traffic events use a typed traffic evidence snapshot; they do not receive a bunching-only FK. |
| `bunching.diagnosis_outbox` | `disruption.planning_outbox` | Copy stable event/idempotency identity, status, attempts, retry deadline, lease, last HTTP status, sanitized failure and delivery timestamps. Keep payload fingerprint/snapshot needed for exact retry. |
| `diagnosis.diagnosis_request` | `planning.planning_request` | Consolidate producer event key, immutable accepted input, job state, attempts, retry/lease timestamps, failure, created/updated times and version. Preserve idempotency uniqueness and status semantics. |
| `diagnosis.root_cause_diagnosis` | `planning.diagnosis_result` | Preserve cause/subtype, explanation, confidence and evidence-support score, evidence IDs/limitations/components, immutable snapshot/hash, provider/model/prompt/schema versions and completion time. |
| `diagnosis.model_invocation_record` + `recommendation.model_invocation_record` | `planning.model_invocation_record` (or justified typed child tables) | Preserve every attempt, purpose/type, correlation, provider/model, prompt/output-schema versions, start/completion/latency, tokens, outcome/failure category, structured candidate, raw generated response where currently retained and immutable input snapshot. Keep diagnosis and recommendation purposes distinguishable. The exact unified key/nullable columns and current-record collision proof must be settled before import. |
| `diagnosis.recommendation_delivery` | `planning.recommendation_job` or equivalent same-schema durable state | Replace only the HTTP delivery boundary. Preserve queued/processing/terminal state, retry count/deadline, lease, sanitized error/status, canonical payload/fingerprint, response and terminal/delivery timestamps until local planning completion is verified. |
| `recommendation.recommendation_record` | `planning.recommendation` | Preserve stable recommendation ID, canonical request hash and payload, event ID, direction/adjustment JSON projections, immutable mitigation context, validated response, created time and database checks. Drop only duplicate projection columns already retired by applied V004 after verifying catalog state. |
| New traffic lifecycle tables | `disruption.*` | Add source/classification/demo-scoped incident lifecycle and evidence snapshots, idempotent by provider source key. No equivalent active detector table currently exists. |
| Phase 2 approval/binding/instruction data | None in phase 1 | Explicitly deferred; do not create tables or placeholders. |

## Source schema inventory and transition invariants

Latest active business tables, after applying all migrations:

- `disruption`: `source_processing_state`, `consumer_state`, `alert_processing_state`, `alert_event`, and `diagnosis_outbox`; plus new traffic lifecycle/evidence records. V13 already merged old source retry/rejection/consumer/alert state and removed those superseded tables; do not import tables absent from the latest catalog as if still active.
- `planning`: `diagnosis_request`, `root_cause_diagnosis`, diagnosis `model_invocation_record`, `recommendation_delivery`, `recommendation_record`, and recommendation `model_invocation_record`.
- `ingestion`: the 12 entity tables and current views inventoried above.

Required reconciliation by natural key: ingestion primary/business keys; disruption source observation UUID and `(classification, demo_run_id, service_id, stop_code, direction_id)`; event IDs plus event action/type; outbox event/idempotency key; planning request `(event_type, producer, event_id, schema_version)`; diagnosis request/result IDs; recommendation ID/request hash; each invocation UUID and typed correlation/purpose. Compare source/target counts, key sets, evidence hashes, live/demo partition counts, active state, all non-terminal jobs, leases and outbox deliveries. Quarantine and explain every collision or invalid legacy row. Preserve no-cross-schema-FK behavior and use logical references/snapshots after import.
