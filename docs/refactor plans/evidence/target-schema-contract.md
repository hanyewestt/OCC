# Phase 1 target schema contract

Status: proposed physical contract for work packages 1.1/1.3. It is derived from the latest applied source migrations and accepted service ownership. The source column-by-column map is [source-column-mapping.csv](source-column-mapping.csv); exact replayed source DDL metadata is [source-schema-catalog.json](source-schema-catalog.json), with source migration SHA-256 values in [migration-checksums.csv](migration-checksums.csv). Do not cut over until the target migrations and importer tests prove the rules below against PostgreSQL/PostGIS.

## Ownership and retention boundary

| Schema | Owner | Tables and rows | Retention and access |
| --- | --- | --- | --- |
| `ingestion` | Ingestion | Existing raw/provider, normalized arrival and traffic observation, polling/feed, reference topology and demo facts | Keep the applied V001–V017 history and DDL, including owned `raw_observation_feed_sequence_seq`; record its actual state at write pause and do not reset it. Apply current configured retention and existing protection rules from `RetentionService`; Disruption and Planning use bounded Ingestion APIs, never direct SQL. |
| `disruption` | Disruption | Bunching checkpoint/state/events, typed disruption lifecycle/evidence, traffic lifecycle/state, producer outbox, import ledger | Preserve active events, all unconsumed/retry/leased rows and protected simulation runs. Apply configured operational TTL only to terminal/resolved data when the source is absent or no longer needed. |
| `planning` | Planning | Accepted requests, diagnosis results, recommendation jobs/results, typed model invocation evidence, import ledger | Keep result and model input/output evidence under the existing retained-evidence policy. TTL may remove only completed delivery/request operational state that is unreferenced; never erase evidence to make a legacy import pass. |

The Ingestion source schema is unchanged. No target runtime foreign key, ORM association, or join crosses a service schema. Logical IDs and immutable evidence snapshots cross HTTP boundaries. User data, test secrets, and provider credentials are not part of this schema contract.

### Traffic lifecycle boundary

The old application stores traffic incident observations in Ingestion but has no traffic detection lifecycle. Preserve those source rows as immutable provider facts. Disruption consumes a bounded endpoint that identifies the poll outcome/completeness and observations for each scope. A replayed poll must be idempotent; two complete responses for the same identity update one state, while a changed provider snapshot emits one update. An absent record counts only when the poll is successful and explicitly complete for that scope. Configure and document the absence count/freshness threshold; test complete, incomplete, failed, stale and replay cases. Migration seeds no inferred clear event and sends no historical event to Planning.

## Constraint and index mapping rules

1. Every current source object, field, PostgreSQL type, nullability, default, primary key, foreign key, unique/check constraint and index is in `source-schema-catalog.json`; every legacy field has exactly one destination row in `source-column-mapping.csv`. The source migration bytes are checksummed in `migration-checksums.csv`.
2. Keep all Ingestion DDL, names, constraints and indexes unchanged. For moved tables, keep a semantically equivalent named key/check/index, rewriting only schema/table/column identifiers and same-schema FK targets. Preserve existing partial predicates and sort order. Do not create a cross-service FK.
3. Target-only constraints listed above supplement copied invariants. Name target constraints/indexes using the conventions in `docs/CONVENTIONS.md`; query plans must justify non-unique indexes. Add `NOT NULL` only after import/backfill proves every row satisfies it.
4. Before DDL is frozen, compare the new empty target schema's catalog against this contract; include full definitions, predicate, null treatment and referenced target keys. Any intentional semantic change needs a recorded ADR and a row-level backfill/reconciliation rule.

The shared invocation row widens differing source `VARCHAR` limits without truncation: `failure_category` 80, `model` 128, `outcome` 32, `output_schema_version` 80, `prompt_version` 80, `provider` 32, and `provider_response_id` 255 characters. Other merged fields retain their identical source PostgreSQL type. The import test must insert each source value at its original maximum length and compare it byte-for-byte after migration.

## Import/cutover invariants

- Keep the old schemas and applied Flyway histories intact during code migration, rehearsal and the MVP write-pause cutover. No production data or persistent Compose volume is touched by local implementation.
- Back up, stop source writers, reconcile/expire in-flight leases under documented rules, import with constraints enabled, compare row counts/key sets/hashes/live-vs-demo partitions/all pending work/evidence, then start one generation of consumers.
- Re-import is safe after process interruption. Verify ledger/source-row hash and target row/hash before declaring a prior row complete. Quarantine invalid rows with reason and source key; no unexplained loss is acceptable.
- Initial recovery before target writes resume is a verified backup restore. After target writes resume, rollback must stop writers and reconcile target deltas or restore with a declared loss window; swapping containers alone does not restore migrated state.
